01. System Context

Early-Stage Ranking in Recommender Context

Compute-vs-Quality Tradeoff

Recommender systems use a multi-stage funnel to balance inference-time compute and quality, similar to LLM early-exits. Fast, lightweight models filter massive candidate pools early, reserving heavy compute for the final few.

Two Main Drivers of ESR
  • Inference Pruning: ESR cuts candidate size from $O(3\text{K}) \to O(300)$, saving downstream LSR from heavy feature cross computation.
  • Selection Bias: LSR learns from a 10 : 300 supervision ratio. ESR must score 3,000 items from those same 10 impressions (a 10 : 3,000 ratio), introducing severe selection bias.

02. Loss Objectives

ESR: Hybrid Supervision & Loss Formulations

Because ESR sits between Retrieval (billions $\to$ 3K) and LSR (300 $\to$ 10), it leverages a hybrid training objective to balance generalization with precise ranking.

Three Pillars of ESR Training
  • BCE (Impressed Data): Models click and conversion probability directly on items the user actually saw.
  • Softmax (Sampled Negatives): Retrieval-style contrastive loss. Learns representations separating positive clicks from random negatives.
  • Rank-Order Alignment (Distillation): Matches relative rank ordering predicted by the heavy downstream LSR using logged funnel data.
Parallel to LLM Alignment

This hybrid approach mirrors LLM optimization: Softmax acts like contrastive Pre-training, while BCE and Rank alignment serve as **Preference Alignment** (RLHF/DPO) to refine rankings.

ESR Loss Objectives Breakdown
1. Softmax Loss (Contrastive)

Maps broad representation space against sampled negatives.

2. BCE Loss (Discriminative)

Learns click/interaction probability on sparse user impressions.

3. Rank Alignment (Distillation)

Distills and aligns rank order with downstream LSR predictions.

03. Core Architecture

ESR Lifecycle: Training vs. Disaggregated Serving

Training (Offline)
  • Twin Towers: Simultaneously learns User and Object embeddings in $D$-dimensional space.
  • OverArch: Combines tower outputs to generate task predictions, computing training losses.
Disaggregated Serving
  • Offline Part: Item embeddings are pre-computed using the Object Tower and published directly to GPU memory.
  • Offline Rationale: Object features change slowly (domain-dependent), so offline pre-computation has minimal freshness impact while avoiding $O(\text{candidates})$ online computation scaling.
  • Online Part: Runs User features through the User Tower online to get the User embedding, retrieves Object embeddings from GPU memory, and inputs both to the OverArch on-the-fly to output predictions used to rank.

04. Serving Variation

Latency Hiding: Parallel User Tower Execution

Normally, ESR scoring runs sequentially after candidate retrieval. However, we can optimize latency by parallelizing User Tower execution.

Online Latency characteristics

Online serving time is typically dominated by the User Tower MLP inference ($T_{\text{User Tower}} \approx 5\text{ms}$), while candidate retrieval also takes time ($T_{\text{Retrieval}} \approx 8\text{ms}$).

The Parallel Optimization
  • Concurrent Trigger: Fire the online User Tower at the same time candidate retrieval is called.
  • Caching: Store the resulting User embedding in a fast online cache.
  • Hiding Latency: When Retrieval completes, fetch the cached User embedding. The post-Retrieval path is now restricted solely to the vectorized OverArch evaluation ($T_{\text{OverArch}} \approx 2\text{ms}$).

05. Serving Bottleneck

Moving Early Stage Ranking (ESR) to GPU Serving

Serving ESR on GPUs improves candidate scoring compute, but hits a severe hardware constraint: GPU HBM Capacity.

The HBM Constraint
  • Memory scale: Storing standard FP16 embeddings for 1 billion items requires 512 GB—far exceeding single GPU limits.
  • Latency constraint: Host CPU streaming via PCIe introduces network delays violating the strict ESR sub-millisecond budgets. Keeping embeddings directly in HBM is mandatory.
  • The Solution: Quantization and compression are required to pack the entire candidate corpus directly into GPU memory.

06. Linear Quantization

Scalar Quantization & Offline Metrics

Post-Training Scalar Quantization (PTQ) maps floating point numbers to signed 8-bit integers (int8), halving memory footprint immediately.

The Math
$$q = \text{clamp}\left( \text{round}\left( \frac{x}{S} \right) + Z, -128, 127 \right)$$

Where S (Scale) and Z (Zero-point) map dynamic ranges: S = (max - min) / 255.

Validation & Offline Metrics
  • Recall @ K: Evaluates candidate recall of LSR top items under ESR quantization noise.
  • Evaluation NE: Measures probability calibration shifts, ensuring downstream scores remain calibrated.

07. Active Mitigation

Quantization-Aware Training (QAT)

When PTQ degrades metrics, Quantization-Aware Training (QAT) models rounding noise directly during training to let the optimizer adapt.

Fake Quantization & STE

Fake-quantization operators simulate integer rounding in the forward pass:

$$x_{\text{fake}} = S \times \left( \text{clamp}\left( \text{round}\left( \frac{x}{S} \right) + Z, -128, 127 \right) - Z \right)$$

Since the rounding derivative is zero almost everywhere, the Straight-Through Estimator (STE) identity-maps gradients during backpropagation.

STE PyTorch Implementation

class STEFunction(torch.autograd.Function):
    @staticmethod
    def forward(ctx, x, scale):
        return torch.round(x / scale) * scale

    @staticmethod
    def backward(ctx, grad_output):
        return grad_output, None
08. Vector Clustering

Product Quantization (PQ)

Product Quantization (PQ) groups vector dimensions into subvectors and applies clustering to exploit correlation across dimensions.

The Method
  • Split: Divide a D-dimensional vector into M subvectors of dimension d = D/M.
  • Cluster: Generate a codebook of K centroids (typically 256) per subspace via K-Means.
  • Index: Replace each float subvector with the 1-byte index of its closest centroid.
Example: D=256 FP16 (512 bytes) compressed into M=80 subspaces takes just 80 bytes. That's an **84% memory savings** with minimal quality loss.

09. Differentiable Clustering

End-to-End Trained PQ

Traditional PQ relies on post-training K-Means. End-to-End Trained PQ (E2E PQ) learns the codebooks and cluster assignments jointly with the ranking model.

Softmax-Weighted Gradients

During training, we represent the reconstructed vector as a differentiable softmax-weighted average over all $K$ codebook vectors:

$$\mathbf{x}_{\text{rec}}^m = \sum_{k=1}^K w_{m,k} \cdot \mathbf{c}_{m,k} \quad \text{where} \quad w_{m,k} = \text{softmax}_k \left( \frac{\mathbf{v}_m \cdot \mathbf{c}_{m,k}}{\tau} \right)$$
Joint Loss

Minimizes ranking loss and reconstruction error to prevent representation collapse:

$$\mathcal{L}_{\text{total}} = \mathcal{L}_{\text{BCE}} + \alpha \sum_{m=1}^M \|\mathbf{v}_m - \mathbf{x}_{\text{rec}}^m\|^2$$

Optimizing & Inference

  • Backward Pass: Gradients optimize codebooks ($\mathbf{c}_{m,k}$) and tower parameters ($\mathbf{v}_m$).
  • Inference: Softmax temperature $\tau \to 0$ makes weights one-hot. Argmax index (1-byte) is saved to GPU.
10. Variance Balancing

TurboQuant

Standard quantization struggles with correlated dimensions or uneven variance. TurboQuant solves this by preprocessing the embedding space.

The Rotation Steps
  • Orthogonal Rotation: Multiplies embeddings by random orthogonal matrix $R$ to preserve similarities ($\langle R x, R y \rangle = x^T y$).
  • Variance Spreading: Redistributes energy evenly across all dimensions.
  • Centroid Fitting: Fits 1D scalar quantizers on balanced dimensions, minimizing rounding noise.

Why Rotate?

Rotating balances uneven dimension ranges (e.g. mapping $[-10, 10]$ and $[-0.1, 0.1]$ to similar scales). This prevents uniform quantizers from clipping high-variance directions or losing low-variance signals.

11. Optimal Rotation & SVD

SpectralQuant

SpectralQuant replaces random rotation with data-driven rotations derived from Singular Value Decomposition (SVD).

How It Works
  • SVD Rotation: Decomposes embeddings ($X = U\Sigma V^T$) and rotates using right singular vectors $V^T$ to align with principal components.
  • Adaptive Bit Allocation: Directions with higher eigenvalues ($\lambda_i$) get more bits, while minor noise directions get fewer:
    $$b_i \propto \log_4(\lambda_i)$$
