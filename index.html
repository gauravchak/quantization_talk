01. Serving Bottleneck

Moving Early Stage Ranking (ESR) to GPU Serving

In modern latency and capacity efficient recommender systems, inference time compute, especially in feature fetching is implemented as a cascaded stack, where retrieval fetches ~2k items from billions, ESR fine tunes down to ~200 and LSR finds the top 2-3 items to show the user.

Serving ESR on GPUs increases throughput of complex ML ops.

The Architecture

During training, the user tower is modeled with U × D embeddings and the object tower maps objects to O × D embeddings. Training utilizes the same user-impressed data as LSR. However, serving constraints differ drastically:

  • User Tower: Inferred on-the-fly using the user's real-time context.
  • Object Tower: Pre-computed offline. All object embeddings (often millions of items) must be pre-loaded into GPU High Bandwidth Memory (HBM) for sub-millisecond similarity lookups.
  • The Bottleneck: GPU memory is highly constrained. A vocabulary of 10 million items at 128 dimensions in BF16 requires 2.56 GB of raw HBM, excluding index structures, model weights, and search libraries (e.g. FAISS).

02. Linear Quantization

Scalar Quantization & Offline Metrics

Post-Training Scalar Quantization (PTQ) is the first line of defense. By mapping floating point numbers (like FP32 or BF16) to signed 8-bit integers (int8), memory is immediately halved.

The Math
q = clamp( round( x / S ) + Z, -128, 127 )

Where S (Scale) and Z (Zero-point) are computed from the dynamic range of each embedding or dimension: S = (max - min) / 255.

Validation & Offline Metrics

Quantization introduces rounding noise. To measure this impact before serving, offline evaluations are run on static test datasets using key ranking metrics:

  • Recall @ K (e.g. Recall@100): Evaluates whether the quantized candidate set overlaps with the original float model's candidates.
  • Evaluation NE (Normalized Entropy): Measures changes in the distribution predictions. Since ESR scores serve as inputs to downstream components, preservation of the probability calibration is crucial.

03. Active Mitigation

Quantization-Aware Training (QAT)

When Post-Training Quantization (PTQ) causes unacceptable drops in Recall@K or Evaluation NE, we transition to Quantization-Aware Training (QAT). QAT models the quantization noise directly during the training forward pass, allowing the optimizer to adjust weights accordingly.

The Mechanism

In QAT, weights and activations are kept in full precision (e.g. float32), but a "fake quantization" operator is inserted. The forward pass simulates the rounding behavior:

x_{fake} = S \times \left( \text{clamp}\left( \text{round}\left( \frac{x}{S} \right) + Z, -128, 127 \right) - Z \right)

Because the rounding step is a step function with a derivative of zero almost everywhere, we cannot compute gradients directly. To bypass this, we use the Straight-Through Estimator (STE).

Straight-Through Estimator (STE)

The derivative is identity-mapped during backpropagation, passing gradients directly to the underlying full-precision weights:

class STEFunction(torch.autograd.Function):
    @staticmethod
    def forward(ctx, x, scale):
        # Simulate quantization rounding
        return torch.round(x / scale) * scale

    @staticmethod
    def backward(ctx, grad_output):
        # Identity gradient pass-through
        return grad_output, None
04. Vector Clustering

Product Quantization (PQ)

Instead of quantizing each individual dimension (which treats values as independent), Product Quantization (PQ) exploits correlation across dimensions by grouping them and applying vector clustering.

The Algorithm
  • Decomposition: Split a D-dimensional embedding vector into M subvectors of dimension d = D/M.
  • Codebook Generation: Run K-Means clustering in each subspace across all items. A codebook containing K centroids (typically $K=256$, fitting in 1 byte) is generated for each subspace.
  • Quantization: For each subvector, find the index of the closest centroid. The floating-point subvector is replaced with a single 1-byte index.
Example: For D=128 in FP16 (256 bytes), splitting into M=16 subspaces of dimension d=8 reduces storage to 16 bytes. That is a **93.75% compression ratio** with minimal quality loss.

05. Differentiable Clustering

End-to-End Trained PQ

Traditional PQ is a post-training operation that relies on static K-Means clustering. This decouples the quantization from the recommendation objective. End-to-End Trained PQ (E2E PQ) resolves this by integrating the codebook and assignments directly into the model graph.

Softmax-Weighted Gradients

During training, we avoid hard quantization (which has zero gradient). Instead, we represent the reconstructed vector as a softmax-weighted average over all $K$ codebook vectors:

x_{rec}^m = \sum_{k=1}^K w_{m,k} \cdot \mathbf{c}_{m,k} \quad \text{where} \quad w_{m,k} = \text{softmax}_k \left( \frac{\mathbf{v}_m \cdot \mathbf{c}_{m,k}}{\tau} \right)

Here, $\mathbf{v}_m$ is the output of the object tower subspace, $\mathbf{c}_{m,k}$ is a trainable centroid, and $\tau$ is a temperature parameter that controls the sharpness of the distribution.

Gradient Flow & Inference

  • Backward Pass: Gradients flow directly back to the object tower parameters (which adjust $\mathbf{v}_m$) and to the codebook vectors ($\mathbf{c}_{m,k}$), optimizing centroids for the ranking objective.
  • Temperature Annealing: During training, $\tau$ is gradually decreased ($\tau \to 0$). The softmax weights approach a one-hot vector.
  • Inference: Hard argmax is applied. The object tower outputs the single index $k = \text{argmax}(w_{m,k})$. Only the 1-byte indices are saved to GPU.
06. Variance Balancing

TurboQuant

Standard vector quantization methods struggle when variance is distributed unevenly across dimensions, or when dimensions are highly correlated. TurboQuant solves this by preprocessing the embedding space prior to quantization.

The Algorithm
  • Orthogonal Rotation: Multiplies the embedding by a random orthogonal matrix $R$. Since $R^T R = I$, distance and inner products (cosine similarity) are preserved:
    \langle R x, R y \rangle = x^T R^T R y = x^T y
  • Variance Spreading: The rotation redistributes energy, balancing the variance evenly across all dimensions.
  • Centroid Fitting: For each dimension, a 1D scalar quantizer (or PQ codebook) fits a set of centroids and replaces values with indices. Because dimensions now share similar value ranges, quantization noise is minimized.

Why Rotate?

If one dimension has a range of $[-10, 10]$ and another $[-0.1, 0.1]$, a uniform quantizer will either clip the high-variance dimension or under-represent the low-variance one. Rotating balances the dimensions, ensuring uniform resolution is highly effective.

07. Optimal Rotation & SVD

SpectralQuant

SpectralQuant is an evolutionary leap over TurboQuant. Instead of a random rotation matrix, SpectralQuant uses data-driven rotations derived from Singular Value Decomposition (SVD).

How It Works
  • SVD Rotation: Decompose the embedding matrix $X = U\Sigma V^T$. We rotate the space using the right singular vectors $V^T$. This aligns coordinates directly along principal components (PCA).
  • Dimension Importance: Each dimension is now orthogonal, with variance proportional to its eigenvalue $\lambda_i$.
  • Adaptive Bit Allocation: Instead of uniform bit widths, allocate bits proportional to:
    b_i \propto \log_4(\lambda_i)
    Important directions get more bits (e.g. 6 or 8 bits), while minor noise dimensions get fewer (e.g. 2 bits or even 0).
